# MailMyPDF Ecosystem Implementation Stage

This stage locks the logged-in ecosystem architecture without coupling individual vertical repositories.

## 22-step roadmap

1. Central entitlement contract.
2. Usage event model.
3. Usage-limit guard.
4. Separate physical-mail charge contract.
5. Shared My Work model.
6. AI/voice gateway boundary.
7. Canonical vertical registry consumption.
8. Authenticated ecosystem shell.
9. Protected vertical launch handoff.
10. Central account/session ownership.
11. Persistent workflow IDs.
12. Document ownership boundary.
13. Usage ledger persistence.
14. Plan/entitlement persistence.
15. Upgrade flow boundary.
16. Mail Center boundary.
17. Assistant context propagation.
18. Voice context propagation.
19. Cross-vertical recent-work aggregation.
20. Notifications boundary.
21. Audit/event boundary.
22. Integration and production verification.

## Non-negotiable boundaries

- MailMyPDF owns user identity and ecosystem access.
- Platform owns reusable contracts and technology.
- Verticals remain independently deployable applications.
- Platform usage billing is separate from physical mailing charges.
- No vertical may create a competing account system.
- No UI may invent usage or billing state when authoritative data is unavailable.
- Production claims require real verification.
