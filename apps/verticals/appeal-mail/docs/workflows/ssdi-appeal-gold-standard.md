# SSDI Appeal — Supreme Authority Gold Standard

## Workflow identity
- Workflow ID: `ssdi-appeal`
- User-facing title: **Appeal an SSDI Decision**
- Pipeline: P03 Appeal / Reconsideration

## Authority-first promise
The workflow analyzes the actual Social Security decision and distinguishes document facts from procedural conclusions. It never invents deadlines, appeal levels, filing methods, medical facts, eligibility conclusions, or outcomes. Procedural claims must be verified against the decision notice or current authoritative SSA sources.

## Landing-page standard
The page must explain decision analysis, authority verification, deadline discipline, evidence readiness, contradiction detection, adversarial validation, human approval, transparent pricing, and provider-backed mailing proof.

## Executable pipeline
`upload → classify → extract → decision/finding analysis → SSA authority verification → deadline check → appeal-path check → evidence-gap analysis → contradiction/timeline analysis → adversarial stress test → response strategy → Gemini draft → independent validation → readiness → human approval → custom price calculation → Stripe → deterministic PDF → MailMyPDF upload → communication → provider → tracking/proof`

## Safety boundaries
- Never invent medical evidence or diagnoses.
- Never assume a five-step SSA appeal path applies without confirming the decision and current SSA rules.
- Never convert a decision date into a deadline without authoritative support.
- Never fabricate medical, employment, or functional facts.
- Never send without explicit user approval.
