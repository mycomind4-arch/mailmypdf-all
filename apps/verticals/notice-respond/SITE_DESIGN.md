# Notice Respond Site Design

Notice Respond is the visual and product-quality benchmark for the MailMyPDF vertical family.

## Position

**Understand the notice. Prepare the response. Mail it with proof.**

The product should feel procedural, calm, trustworthy, and document-first.

## Visual language

Preserve the current paper/document aesthetic, serif display typography, restrained rules, stamp/postmark details, strong whitespace, compact utility typography, accessible controls, and responsive workflow cards.

Avoid generic SaaS gradients, excessive rounded UI, and chatbot-first presentation.

## Homepage architecture

- Header with workflow discovery and primary analysis CTA
- Hero centered on the actual notice received
- Workflow discovery organized by notice/problem type
- Clear process: Upload → Identify → Understand → Respond → Review → Mail → Track → Prove
- Trust/provenance section
- Workflow directory
- Concrete analysis/review UI examples
- MailMyPDF fulfillment bridge
- FAQ
- Ecosystem footer

## Workflow pages

Each workflow page should answer:

- What notice is this?
- Who receives it?
- What should be gathered?
- What does Notice Respond analyze?
- What issues can be identified?
- What response can be prepared?
- What must the user review?
- How is the final response mailed and tracked?

## Application quality

The application should make the case state visible and explain why a finding exists. Findings should be source-linked. Deadlines should distinguish extracted facts from inference. Drafts should be grounded in case documents.

## Gold-standard benchmark

Other verticals should match Notice Respond's level of:

- visual hierarchy
- workflow discovery
- document-first UX
- evidence/provenance presentation
- safety messaging
- responsive behavior
- empty/loading/error states
- review-before-send behavior
- MailMyPDF fulfillment handoff

Do not weaken existing Notice Respond functionality merely to standardize other verticals.
