# Records Request — Canonical SEO Site Structure

Preserve ecosystem-wide navigation and existing functionality. This is the SEO/content hierarchy.

## Public
- `/` — Records Request pillar: request public records from government agencies; record types; how it works; what to gather; AI handles heavy lifting; review; mailing/proof; featured workflows; FAQ; start.
- `/workflows` — Records Request workflow hub: find your situation, search/discovery, choosing a request, category navigation and crawlable authority pages.
- `/how-it-works` — tell us what records you need → AI identifies likely agency/records → organizes request → review/approve → MailMyPDF sends → track/preserve proof.
- `/products`, `/pricing`, `/mail-a-pdf` — ecosystem/product pages.
- `/about`, `/contact`, `/faq`, `/resources/*` — supporting SEO/footer content.
- `/privacy`, `/terms`, `/404` — legal/error.

## Workflow taxonomy
Government/public records; property & code enforcement; law enforcement/public safety; court/legal records; government contracts & finance; personnel/administration; federal records; request follow-up.

## SEO flow
Pillar → workflow hub → request-specific authority page → authenticated workflow. Preserve existing workflow URLs and build authority around real records-request search intent.

## Simplicity rule
AI performs records identification, agency/custodian identification, fact extraction, scope refinement, date-range analysis, jurisdiction/authority analysis, drafting and validation. The user reviews the exact request before mailing.

## Navigation lock
No vertical-specific menu additions. Ecosystem shell remains authoritative.
