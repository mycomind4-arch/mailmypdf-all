# Code Enforcement Records SEO Specification

## Primary search intent

The landing page targets people who need to obtain code-enforcement records for a property, case, complaint, violation, permit, inspection, or enforcement action. It is a workflow landing page, not a generic public-records article.

## Primary title

Code Enforcement Records Request — Get Property Violation & Inspection Records

## Meta description

Create a focused code enforcement records request for property violations, complaints, inspections, notices, permits, citations, photos, and enforcement history. Build and mail your request.

## Canonical URL

`/workflows/code-enforcement-records`

## Required semantic coverage

The page should naturally cover these query families:

- code enforcement records request
- code enforcement public records request
- request code enforcement records
- code violation records request
- property code enforcement records
- code enforcement complaint records
- code enforcement inspection records
- code violation history request
- property violation records
- building code enforcement records
- code enforcement case records

- code enforcement records by parcel number
- code enforcement records by case number
- code enforcement request template
- public records request for code violations
- request code enforcement history

Do not keyword-stuff. Each cluster should have a useful explanatory section, example, workflow step, or FAQ.

## Competitive differentiation

Government sources commonly require users to identify the right department, address, parcel/case identifiers, record types, and date range. Some agencies expose searchable code-enforcement databases, while others require a public-records request. The page should explain both paths and position the workflow as the tool for when the desired records are not already available or when a targeted production is needed.

## Programmatic support pages

Only create pages where the underlying workflow provides unique useful content. Candidate supporting intents include:

- `/guides/code-enforcement-records-by-address`
- `/guides/code-enforcement-records-by-parcel-number`
- `/guides/code-enforcement-records-by-case-number`
- `/guides/request-code-violation-history`
- `/guides/request-code-enforcement-inspection-records`
- `/guides/request-code-enforcement-complaint-records`
- `/guides/request-property-violation-records`
- `/guides/code-enforcement-records-request-template`

Avoid thin city/state doorway pages. Jurisdiction pages should only exist when the application has verified jurisdiction-specific routing/policy data.

## Technical SEO acceptance criteria

- Unique title/meta/canonical.
- One H1.
- Descriptive H2 hierarchy.
- Server-rendered indexable copy.
- Valid Organization/WebSite/Breadcrumb/FAQ structured data where applicable and truthful.
- No duplicate canonical variants.
- Open Graph/Twitter metadata.
- Strong internal links from records-request, property-records, permit, and related workflow hubs.
- Sitemap inclusion.
- Fast initial render and no critical client-only content dependency.
- No hidden keyword blocks or doorway pages.

## Conversion/SEO rule

The page must answer the searcher's question before asking for payment. The CTA should make the next action obvious: **Build a Code Enforcement Records Request**.
